# 周边去哪儿

## 解析需求

使用任务给定的城市和起点坐标。调用高德工具时按工具要求传经纬度，通常为“经度,纬度”。同一轮的每条路线都从该起点独立出发。只有缺少可用起点时才询问用户。

提取地点类型、明确的排除条件、步行时间上限、推荐数量和排序偏好。用户未指定数量时最多推荐 3 个，指定数量时取该数量和 3 的较小值。用户未设时间上限时按步行便利性排序。

## 搜索与算路

1. 用高德 MCP 的周边搜索，以起点坐标为中心，按地点类型或关键词查找候选。将步行时间要求用于估计搜索范围，范围只用于召回。保留高德返回的名称、地址、类型和坐标，按 POI ID 去重。先排除类型不符、明确被用户排除或缺少有效坐标的候选。
2. 搜索时取多于所需推荐数的候选，例如先取 8 个。对这批候选逐个调用高德 MCP 的步行路线规划，以原起点为起点、候选坐标为终点。保留同一条有效步行路线返回的距离与耗时。若返回多条有效步行路线，可选耗时最短的一条。搜到的直线距离只能帮助安排查询顺序。
3. 使用路线返回的原始耗时比较时间上限，统一单位后再比较。例如“不超过 15 分钟”包括 900 秒，排除 901 秒。只有查到有效距离和耗时且满足硬性条件的候选才进入推荐。若首批不足，可在工具支持时再查一批或适度扩大搜索范围，继续按原条件过滤。
4. 在已核实的候选中按偏好排序。“近一点”按步行距离升序，“快一点”按步行耗时升序。没有指定排序时优先考虑已核实的偏好，其次按步行耗时升序。最后截取所需数量。缺少证据的软偏好标注“未核实”，明确的硬性要求只有核实后才视为满足。

## 回答

用列表或表格展示每个推荐的**名称、地址、预计步行距离、预计步行时间和一句推荐理由**。名称与地址采用高德返回的信息，缺少地址时标注“地址未核实”。距离与时间采用算路数据，必要时用分和秒表达，尤其是接近时间上限时。推荐理由应对应用户需求和已核实的数据。

不足目标数量时，返回已核实的结果并简述原因。搜索成功且没有合格地点时说明“在本次查询范围内未找到符合条件的地点”。如果搜索或算路失败，区分已查实的部分和无法核实的部分，保留已查实的推荐。可以建议放宽条件，等待用户决定。营业状态、排队、安静程度等缺少依据时标注“未核实”。
